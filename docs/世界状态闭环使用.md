# 世界状态闭环：当前用法

已实现第一版闭环：聊天正文完整保存 → 当前文本模型额外一次结构化提取 → 有效来源和原文依据校验 → 保存状态与消息节点检查点 → 面板展示 → 下一轮聊天注入。

- 聊天区顶部的“世界状态”默认折叠，展开可查看事实、修正、锁定或解锁。
- 旧故事点击“整理当前剧情”开始建立状态。不会启动即批量处理历史；超过预算只读取最近完整消息并提示覆盖不足。
- 不完整、取消或失败的聊天不触发整理。整理失败保留正文与旧状态，可重试；每次整理最多 90 秒，期间当前故事等待整理完成。
- 整理使用当前文本模型和当前配置密钥，额外消耗一次模型调用。只发送已有状态、参与者名字、需要处理的消息及独立提取规则，不发送完整聊天预设。
- 手动字段默认锁定，包括父子路径覆盖保护。解锁只解除保护，不立即改变内容。
- 状态包含世界/时间、人物、关系、物品、地点、服装、短摘要与自定义事实。模型不得凭空生成好感度、把愿望当事实；原文依据校验不能替代用户判断。
- 重发保留原故事，恢复到被改消息之前最近的状态检查点；旧状态和消息留在本机修订备份。
- 分支复制截至所选消息最近的检查点并重映射消息 ID。没有检查点的旧节点会明确提示尚未整理，不把最新状态带回历史。
- 当前未实现长期记忆向量检索、完整 statspanel 插件兼容、生图 SceneState 自动投影。记忆仅接入短摘要。

后端：`world-state.ts` 受限补丁验证；`world-engine.ts` 提取与保存；`world-text.ts` 聊天服务适配层；SQLite `world_checkpoints` 保存节点状态。保留只读 `text.ts`。

验证：本地模拟模型闭环、锁定、非法来源、错误隔离、完整预设顺序、重启、分支和重发测试。没有向外部模型发送真实聊天进行验收。


## 2026-10-21 稳定性修正

- 原生 Claude Opus/Sonnet 4.6 的 low/medium/high 设置传递为 adaptive thinking 与 output_config.effort；minimal 映射为 low。default 保留不主动开启思考的行为，其他原生型号的非默认设置明确报不支持，不静默忽略。
- 结构化提取请求单独禁用 Claude 思考，不继承聊天级别。
- 世界状态格式、证据或路径校验失败时最多重新生成一次；不携带失败输出，只传回受控校验原因。不放宽来源消息 ID 校验，只容忍原文空白排版变化。
- 分别展示超时、接口错误、JSON 无效、证据不匹配和状态路径问题，保留正文及上一版状态。旧版统一错误无法追溯具体原因。
- 状态整理总等待上限 180 秒（底层接口仍可能更早超时）；不会自动重发聊天。
