# SillyTavern 聊天预设导入

在「设置 → 文本模型 → 聊天预设」导入 JSON，再保存。原始 JSON 文本随模型持久化，可完整导出；未启用条目和未知字段不会被删除。清除完整预设后才使用简版叙事规则。

当前实现：

- 选择 `prompt_order` 的 100001 配置（不存在时选择第一套），遵守 enabled 和顺序。
- 支持相对顺序的 system/user/assistant 提示词、角色描述、性格、场景、聊天历史占位符。
- 支持 setvar、getvar、addvar、trim、char、user、lastUserMessage。变量每次编排独立初始化，不执行代码。未知宏明确报错。
- 保留历史前后提示词位置，按 squash_system_messages 合并相邻系统消息。上下文预算包含完整编排。
- 导入温度、上下文、最大输出、思考级别；官方 DeepSeek 聊天请求附带 top_p、frequency_penalty、presence_penalty。思考模式下供应商可能忽略采样参数。
- 生图状态推断不注入聊天预设。

兼容性边界（不等于完整 SillyTavern 运行环境）：

- MVU 插件、变量 schema/初始值、世界书和脚本不包含在普通提示词预设中。当前不会执行 UpdateVariable/JSONPatch，不会自动加载世界书；worldInfo 占位符为空。
- 未绑定人设时用户身份使用「旅人」；绑定后使用聊天人设快照的姓名与资料。示例对话从原角色卡 mes_example 读取为系统素材，尚非 SillyTavern 多消息示例解析。
- 群聊、冒充、续写专用操作、工具调用、多模态、reasoning_content 展示等字段原样存档，不宣称执行。
- 深度注入预设明确拒绝导入，不能静默变为相对顺序。
- 目前上下文仍按保守 UTF-8 字节计数，不是模型精确 tokenizer。

对奥涅伊洛斯 MVUZOD-v1.0：原文件 46 个提示词条目，100001 顺序中启用 35 项；完整模式不再使用之前手工抽取的日常叙事精简版本。原始最大输出 100000、上下文 1000000、思考 high。

完整导入预设不代表缺失插件已得到实现。要还原 MVU 整套行为，仍需实际使用的角色卡、世界书、变量定义与插件配置。
