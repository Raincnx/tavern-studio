# 画面状态与身份分离

实现日期：2026-10-17。

交互更新：点击聊天消息的“绘制这一刻”会打开生图面板并自动提取该时刻状态；直接点击“生成这一刻”会先补齐当前剧情状态，再提交生图。正常界面只显示场景、人物、衣着和动作表情摘要，手动字段、参考设置和完整提示词默认收在“调整画面（可选）”。用户不需要逐项填写状态。推断失败或取消不提交生图，文本服务离线时给出启动或切换模型的明确提示。

## 数据与优先级

- `VisualProfile` 保留现有角色参考和服装基准，兼容原卡片，不批量改写用户资料。
- `SceneState.identity` 是模型提取后可手动修改的稳定五官、年龄段、肤色、自然比例和辨识特征。
- 每个人有独立编号，主角为 `main`；位置、动作、表情、服装款式、穿着状态、发型及配饰状态、道具分别保存。
- 时间地点与光线、镜头、接触遮挡单独保存。明确区分入镜和镜头外的人物。
- 每个事实记录明确剧情、继承、不确定或手动指定及来源消息。手动修正不会被同一时刻或更早的自动推断覆盖，之后明确发生的变化可以覆盖。

## 推断与保存

新的网页使用 `/image-prompts` 的 `structured: true` 模式。每次最多处理 4 条完整消息；预算不足时缩小批次，单条仍超预算则报告错误，不静默截断或跳过。浏览器自动继续下一批，展示剩余消息数，支持取消。

每批成功后，`scene_states` 按会话和截止消息保存快照。快照记录之前全部消息的内容指纹和当时角色/服装参考指纹。重新打开页面、服务重启或推断取消后，可以从有效快照继续。过去消息不能读取未来快照；历史正文、角色资料或服装参考变化后，不匹配的快照不再复用。重写早期快照会使后续快照失效。

`GET /scene-state` 返回可继承状态、剩余消息数与并发校验 key。`PUT /scene-state` 保存手动状态，校验剧情未变化。第一遍读取长对话需要多次模型请求；之后只处理新增消息。现有项目没有消息编辑/分支 UI，内容指纹已覆盖存储层正文变更。

## 生图与预览

`POST /image-prompts/preview` 和任务提交使用相同的后端编译函数。结构化状态是人数、衣着与动作的依据，原文本框变为画面补充。

参考图仅绑定主角：脸图约束稳定五官，全身图约束自然比例，服装图约束当前款式。服装变化时不再传旧的专用服装图；全身参考仍可用于比例，并明确排除旧服装与姿势。主角不入镜时不传其参考图。状态和编译提示词随任务冻结，图片归档保留当时状态。

兼容旧客户端的纯文本模式仍可使用，但没有结构化状态时间线。旧角色卡里混入的服装和环境不会被直接删除；新推断负责提取稳定身份，用户可在状态面板修正。模型语义判断与人体质量无法用字段校验保证，仍需要真实生图验收。

## 验证

自动化覆盖分批读取、历史状态继承、来源校验、旧消息回溯、正文变更失效、重启恢复、手动优先级、错误 JSON、多人参考归属、预览/提交一致、任务归档冻结。独立模拟服务完成浏览器推断、编辑表情、保存、提示词预览和刷新恢复验证。

本地文本与生图服务按用户要求保持暂停，本次未进行真实模型出图评估。
